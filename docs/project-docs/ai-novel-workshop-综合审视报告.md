## 三、跨角色共识（所有角色共同发现的问题）

### 3.1 SandboxLayout.vue 脱离设计系统（UI设计师 + 产品经理 + 开发工程师一致）

- 三个角色独立发现同一问题：`SandboxLayout.vue:82-84` 使用硬编码 `#fff` 白色背景和 `#e4e7ed` 边框
- 暗色主题下出现白色块，视觉完全断裂
- **修复建议**：使用 `--ds-surface`、`--ds-border` 等Design Token替代

### 3.2 测试覆盖严重不足（开发工程师 + 测试工程师一致）

- 开发工程师统计覆盖率约26%，测试工程师统计约20%
- 76个Vue组件零测试、16个核心服务无测试
- 安全关键工具（inputSanitizer、crypto）无测试覆盖
- 无CI/CD集成、无E2E测试、无coverage报告

### 3.3 存储架构分散（产品经理 + 开发工程师 + 测试工程师一致）

- 三种存储机制并存：localStorage + IndexedDB + SQLite(Tauri)
- Web模式Sandbox使用localStorage，容量限制5-10MB，大型项目将超限
- 测试工程师进一步指出：saveChapter/saveProject存在竞态可致章节正文丢失

### 3.4 Token估算公式冲突（开发工程师 + 测试工程师发现）

- 4处不同实现，公式方向相反：`pipeline.ts:68` 用 `*1.5`，`tokenizer.ts:52` 用 `/1.5`
- 直接影响AI上下文预算准确性

## 四、各角色独特发现（其他角色未覆盖的洞察）

### 4.1 产品经理独有发现

1. **产品定位分裂**：README定位"AI长篇小说生成工具"，DESIGN.md定位"互动式同人小说生成器"并写"推倒重来"，方向未明确
2. **冷启动门槛高**：用户需自带API Key才能使用任何AI功能，无免费体验模式
3. **信息架构过载**：9+一级导航入口，SandboxLayout内部还有4个子Tab
4. **竞品分析**：与Sudowrite/SillyTavern/橙瓜码字对比，AI小说工坊在技术架构上领先但UI打磨和新手引导落后
5. **模板映射不直观**："快速大纲"模板实际映射到都市模板

### 4.2 UI设计师独有发现

1. **暗色主题品质高**：深空紫4级背景 + 紫色accent + 径向光晕，设计精良
2. **亮色主题Token不完整**：accent/success/warning/danger/info语义色未重定义
3. **品类色带系统**：项目卡片按小说类型自动匹配不同渐变色带，有温度的设计
4. **Z-index无统一管理**：9999/10000/999等值分散各处
5. **工具函数重复定义**：formatNumber/formatDate在4+组件中重复
6. **ECharts图表颜色未适配主题**：硬编码颜色在亮色下可能对比度不足

### 4.3 开发工程师独有发现

1. **Token估算公式冲突**：4处重复实现且方向相反
2. **熔断器按Provider维度共享**：同Provider不同模型失败互相影响
3. **CostTracker.records无限增长**：内存泄漏风险
4. **Element Plus全量导入**：约500KB+体积浪费，最大单一优化点
5. **knowledge-base.ts的generateUid碰撞概率极高**：`Date.now() % 1000000`
6. **V1→V5迁移chapterNumber硬编码为1**
7. **taskManager.ts运算符优先级错误**：`task && task.status === 'running' || task?.status === 'pending'` 缺少括号
8. **已完成但有遗漏的功能**：embedDataInPng未实际嵌入数据、dataAPI.getMemory返回空数组

### 4.4 测试工程师独有发现

1. **reportExporter.ts XSS高危漏洞**：generateReportHTML未转义直接拼接HTML并document.write输出
2. **AI fetch无超时保护**：SSE流无超时，LLM挂起时请求永久阻塞
3. **crypto.randomUUID() 9处中8处无降级**：非HTTPS环境直接崩溃
4. **多标签页无乐观锁**：两个标签页同时修改时后保存覆盖先保存
5. **public/目录含调试文件**：含11.2MB sync-payload.json和多个调试HTML
6. **响应式设计几乎空白**：仅4处@media查询
7. **后端API Key明文存储**：`backend/app/models/user.py:12`
8. **无browserslist声明、无Autoprefixer**

## 六、综合优缺点总结

### 核心优点（各角色共识）

1. **Entity & StateEvent事件溯源架构**：产品经理（8/10）、开发工程师均认为领先同类产品
2. **AI调用容错体系完善**：重试+熔断+故障转移+限流，开发工程师和测试工程师均给出高评价
3. **暗色主题设计品质高**：UI设计师给出详细好评，产品经理也认可
4. **安全意识较强**：开发工程师和测试工程师均认可（DOMPurify、输入校验、ReDoS防护）
5. **插件架构设计精良**：10种扩展点，产品经理和开发工程师均认可
6. **防御性编程出色**：projectBackup 10+项校验、reviewParser边界检查等
7. **四层模型路由设计成熟**：planner/writer/sentinel/extractor分层策略

### 核心缺点（各角色共识）

1. **产品定位分裂**（产品经理）：README vs DESIGN.md方向冲突
2. **冷启动门槛高**（产品经理）：无免费体验，需自带API Key
3. **SandboxLayout脱离设计系统**（UI设计师+产品经理+开发工程师）：暗色主题视觉断裂
4. **测试覆盖严重不足**（开发工程师+测试工程师）：20-26%，76个组件零测试
5. **存储架构分散且有数据丢失风险**（测试工程师重点发现）：竞态、localStorage容量限制、IndexedDB升级删库
6. **Token估算公式冲突**（开发工程师）：4处实现且方向相反
7. **XSS漏洞**（测试工程师）：reportExporter.ts高危
8. **AI调用无超时保护**（测试工程师）：fetch无AbortSignal
9. **兼容性薄弱**（测试工程师）：无browserslist、crypto.randomUUID无降级
10. **代码重复度高**（开发工程师）：estimateTokens 4处、Provider SSE 3处

## 七、综合修复建议（按紧急程度排序）

### P0 — 必须立即修复

1. **reportExporter.ts XSS漏洞**：`generateReportHTML` 中所有动态数据必须HTML转义
2. **saveChapter/saveProject竞态**：在saveProject中保留已有章节的content字段
3. **IndexedDB升级删库**：实现版本迁移逻辑替代deleteDatabase
4. **SandboxLayout样式修复**：替换硬编码颜色为Design Token

### P1 — 高优先级修复

5. **AI fetch添加超时控制**：所有fetch调用添加AbortSignal超时
6. **localStorage sandbox容量保护**：迁移到IndexedDB或添加容量检查
7. **crypto.randomUUID降级方案**：8处直接调用添加非安全上下文降级
8. **Token估算公式统一**：消除4处重复实现，统一为一个函数
9. **public/目录清理**：移除调试文件和11.2MB sync-payload.json

### P2 — 中优先级改进

10. **明确产品方向**：README和DESIGN.md统一
11. **设计冷启动体验**：提供内置免费额度或体验模式
12. **Element Plus按需导入**：可节省约500KB+打包体积
13. **补充安全关键模块测试**：inputSanitizer、crypto、CircuitBreaker
14. **后端API Key加密存储**
15. **统一错误处理模式**：消除throw/静默吞没/返回null混用

### P3 — 低优先级优化

16. **精简信息架构**：合并低优先级导航入口
17. **补充响应式设计**：至少为主布局添加移动端适配
18. **亮色主题Token补全**
19. **Z-index统一管理**
20. **清理V1废弃类型**
